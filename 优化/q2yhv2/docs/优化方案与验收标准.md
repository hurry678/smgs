# 问题二 DS 高算力优化方案与验收标准

## 1. 目标与基线

优化对象是 `ds` 已冻结的 `M3-ensemble9 + C2`，不是 `优化/q2yh`。旧基线由 9 个同构
M0 模型组成，分类取 softmax 概率均值，强度取 raw intensity 均值。

冻结基线：

| 指标 | valid | test（历史描述值） |
|---|---:|---:|
| Accuracy | 0.620879 | 0.635488 |
| Macro-F1 | 0.599707 | 0.596337 |
| MAE | 0.579967 | 0.643349 |
| Pearson | 0.663537 | 0.657517 |
| 缺失 R_MAE | 0.604523 | 不适用 |
| 缺失 R_F1 | 0.572749 | 不适用 |
| 最差条件 MAE | 0.650466 | 不适用 |

任何新方案只有通过预注册的 validation confirmation 门槛才可替代旧基线。

## 2. 为什么不继续改网络

已有证据表明：

- M1-balanced 的三种子 `R_MAE=0.631626`，差于原 M0 均值；
- M2-cross-time 的 seed42 `R_MAE=0.620249`，差于原 M0 seed42；
- 均匀扩大到 12 个 M0 后 `R_MAE=0.606308`，差于 6/9 模型集成；
- q2yh 的 B3+SAM+L2 在 valid/test 均明显落后于 DS。

因此当前主要瓶颈不是网络容量，而是小样本训练方差、任务损失权衡、缺失增强分布和集成成员
质量。新增算力用于降低这些方差，并保留 M0 的可解释缺失结构。

## 3. 严格数据协议

### 3.1 train 内部搜索

按 `sample_id` 中 `$_$` 前的视频 ID 分组。同一视频的片段不得
跨折。12 个训练变体使用相同 3 折划分和同折训练种子，比较单位是折级配对结果。

交叉验证阶段只读取原 train：

- 每折归一化统计只由该折训练部分估计；
- 早停只看该折 holdout；
- 每折最终用 21 个缺失单元格、2 个固定复本评价；
- 根据 3 折聚合结果选 4 个训练变体；
- 每个变体的最终训练轮数取 3 折最佳轮数中位数。

### 3.2 valid 两阶段

最终候选用完整 train、固定轮数训练，不读取 valid 做早停。

原 valid 再按视频组确定性拆成两个不相交分区：

- selector：`mask_seed=2026`，每单元格 3 复本，只用于选集成成员与权重；
- confirmation：`mask_seed=20261001`，每单元格 5 复本，只用于一次性通过或回退。

confirmation 不允许修改成员、权重、发布规则或任何超参数。

### 3.3 test 与无标签附件

- test 在冻结前不读取；
- test 已被历史版本暴露，因此新版本中只能报告描述结果；
- 附件 3 只执行冻结推理；
- test 或附件 3 的结果都不得触发重训、换成员、改权重或改阈值。

## 4. 搜索空间

所有候选均使用 DS 的 M0 结构、MiniLM-L6-v2 冻结文本编码器、双任务头和 C2 发布。

| 组 | 改动 |
|---|---|
| A00 | DS 原训练配置 |
| A01-A02 | warmup-cosine 与较低学习率 |
| A03 | EMA，衰减 0.99 |
| A04-A05 | 缺失视图模仿完整视图的一致性约束 |
| A06-A07 | 回归损失权重 0.75/1.25 |
| A08 | Huber beta 0.5 |
| A09 | 提高含文本缺失组合的训练概率 |
| A10 | 平方根逆频率类别权重 |
| A11 | dropout 0.10 |

不做全笛卡尔积，避免在有限数据上产生不可审计的超参数挖掘。

## 5. 集成选择

候选池包含：

- 旧 DS M3 的 9 个成员；
- train 内部 CV 排名前 4 个变体各 12 个新种子。

选择器先按单模型综合目标保留最多 28 个成员，并始终保留 9 个旧成员。随后从旧 M3 等权
状态开始，执行加成员、删成员、替换成员三类坐标搜索。

约束：

- 5 至 13 个权重槽位；
- 至少 5 个不同成员；
- 单成员权重不超过 0.25；
- 最多 12 轮；
- 改善小于 `1e-5` 时停止。

综合目标对以下指标按旧 M3 归一化：

```text
J =
  1.00 * R_MAE
+ 0.35 * (1 - R_F1)
+ 0.25 * clean_MAE
+ 0.15 * (1 - clean_F1)
+ 0.15 * worst_condition_MAE
```

目标只负责搜索方向，最终候选还必须通过 selector 硬门槛。

## 6. Confirmation 门槛

相对旧 M3，在独立 confirmation 分区上必须同时满足：

| 指标 | 门槛 |
|---|---:|
| R_MAE 改善 | 至少 0.0005 |
| R_F1 降幅 | 不超过 0.003 |
| clean MAE 增量 | 不超过 0.002 |
| clean Macro-F1 降幅 | 不超过 0.003 |
| 最差条件 MAE 增量 | 不超过 0.003 |

只要一项失败，即保留旧 M3。这里的回退是预注册验收规则，不是根据 test 反向选模。

## 7. 工程约束

- 旧检查点、数据和 DS 核心脚本均做 SHA-256 校验；
- 基线必须在 `1e-6` 绝对误差内复现；
- 所有任务输出独立目录，可断点续跑；
- 新检查点不保存重复的冻结 BERT 参数；
- 冻结包按 `Q1 24,015,744 bytes + Q2 紧凑成员 + Q3 5,000,000 bytes` 预估；
- 预估总大小超过 50,000,000 bytes 时拒绝冻结；
- `worst_condition_F1` 定义为各条件 Macro-F1 的最小值。

## 8. 论文表述边界

服务器运行前只能称为“预注册优化方案”，不能声称性能提升。运行后：

- confirmation 通过：可写“在预注册 confirmation 条件下通过替换门槛”；
- confirmation 未通过：应报告负结果并继续使用 `M3-ensemble9 + C2`；
- 即使 test 更好，也不能写成独立测试验证，因为该 test 已被历史流程使用；
- 算力规模、失败候选和回退结果都应保留，不能只报告最优成员。
