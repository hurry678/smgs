# 实验矩阵、模型选择与验收

## 1. 预算与分阶段执行

预算是本轮工程默认，可在第一次训练前按实测吞吐缩减，并写入`execution_plan.json`；
不能先看valid成绩再为某个候选增加搜索预算。建议总墙钟上限12小时，
前6小时确保P0和必需因子分析，预留至少2小时用于最终预测、冻结、打包和报告。
GPU可把独立实验分配到不同卡，但同一对比固定卡型、精度、batch和软件版本。
不为4850条样本默认启用分布式训练。

| 阶段 | 实验与数量上限 | 产物 / 停止条件 |
|---|---|---|
| S0 预检 | 全量train/valid＋附件3接口，原始SHA、环境检查 | preflight、模型资源校验、只读基线快照 |
| S1 冒烟 | B2、M1，128个train样本×2epoch，32个valid仅检查数值 | 前后向、缺失测试、资源和epoch吞吐；禁止论文引用冒烟分数 |
| S2 P0主线 | B0；B2、M1各seed42；M1另跑CE+MSE及clean-only对照 | 先有可冻结小模型、双任务验证与全部30条推理所需代码 |
| S3 架构筛选 | B1、B3、M2、M3各seed42；共不超过8个神经训练run（含S2） | 同损失L1/O1，63条件select库＋clean；排除数值/包体失败 |
| S4 优化算法筛选 | S3前两结构：O2的2个lr、O3的2个rho、O4的1配置，共≤10run | 所有训练run记录失败；资源不足先O3/O4各1配置，O2按推荐lr0.03 |
| S5 损失/稳定化 | 初步最优结构，λ_r=0.5/2、L2、L3、EMA，各≤1run；最多5run | 相对L1 λ=1对照，逐项改变，不叠加后宣称单机制效果 |
| S6 多种子确认选择 | 前两完整配置补seed43/44；机制对照按下述要求补齐 | 禁止最佳种子挑选；允许沿用完全相同配置的seed42结果 |
| S7 冻结后验证 | confirm＋position＋coupling；可选stress；冻后test描述性审计 | 全量逐样本预测、聚类区间、误差分析；不根据confirm/test改模型 |
| S8 附件3 / 交付 | 固定checkpoint+normalizer+发布规则推理30条 | CSV、JSON、说明、完整可加载权重、SHA、合包字节数 |

除冒烟外，默认总神经训练上限36run。P2的M4、M5、O5只在完成P0、必需规律分析、
多种子和交付后且未超预算时开，须从剩余预算扣除；未执行写`not_run_budget`。
如果12小时不足，按P2→S5→S4→M3的顺序削减，保留B2、M1及三因素分析。

单模型默认：hidden=64，BiGRU=1层，batch=64，epochs≤25，patience=5，
min_delta=1e-4，梯度clip=1.0；前两个epoch测吞吐后输出预计总时长。
train_seed∈{42,43,44}，augmentation_seed固定为`10000+train_seed`，
所有候选的同一种子共享数据顺序与增强样本；评价种子独立。
单模型不得超过2M可训练非编码器参数；超限候选降级为P2并记录，不能隐瞒额外容量。

## 2. 冻结的选择规则

所有结构、优化器、损失、集成规模和发布策略只在select验证库选择；
输出`selection.json`包括全部候选、拒绝原因、差值及配置。

主指标为发布强度的 `R_MAE`：先对每个“子集×比例”的3个复本MAE取平均，
再对21个条件等权平均。分类 `R_F1`、`R_Accuracy`和Pearson用相同汇总顺序；
不得把不同条件预测混成独立新增样本。clean不加入R_MAE，单独报告。

固定工程规则：

1. 覆盖、有限值、掩码、标签、原数据保护、发布一致性、权重可加载与预计包体等硬门先过。
2. 相对同种子B2基线，候选平均clean Macro-F1最多下降0.02、clean MAE最多增加0.02、
   R_F1最多下降0.01、最差条件MAE最多增加0.03；否则仅保留权衡分析，不自动推荐替换。
   B2作回退，不因其他候选失败而导致无交付。
3. 在合格候选中找最小种子平均R_MAE；差≤0.005者列为工程近似并列。
4. 并列集合按R_F1降序；差≤0.005时按最差条件MAE升序；其差≤0.005再优先权重小、
   推理快的方案。容差是预注册工程折中，不是统计等效检验。
5. 最终候选与主要基线必须完成同样3种子。少于3种子只能写`provisional_single_seed`，
   禁止声称鲁棒性机制或稳定性已验证。默认部署seed42，不选valid最好seed。
   如3模型等权集成也通过同规则且包体允许，可部署预先定义的{42,43,44}；不能再挑子集。
6. 若新方案相对旧ds只得到跨接口结果，不以绝对小数直接声称改进；旧权重在新协议重评后才可做同表对照。
   如果旧权重缺失，注明`legacy_not_replayed`，不阻塞新P0。

C2为默认主策略。可选C3仅在模型/loss候选缩至前两项后做固定9对阈值；
发布策略也必须在select阶段冻结。不同发布策略不能一个报raw MAE、另一个报投影后MAE。
强度一致性无需依赖调阈值才能达标。

## 3. 机制消融（先做与题目直接相关的）

| 对比 | 保持不变 | 回答的问题 |
|---|---|---|
| M1 clean-only vs M1 synthetic-missing | 编码器、结构、loss、optimizer、训练步数 | 收益是否主要来自局部缺失增强 |
| B3 vs M1 | 容量匹配、硬掩码和其他训练配置 | 显式二进制掩码侧通道是否有用 |
| M1 vs M2 | 编码器、训练、输出规则 | 连续缺失位置/跨度是否提供额外信息 |
| M2 vs M3 | 训练与预算，报告新增参数 | 跨时刻attention是否有用，是否过拟合 |
| CE+MSE vs CE+Huber | 固定结构O1与任务权重 | 改善来自损失选择还是结构 |
| 单任务分类/回归 vs 双任务 | 同一编码器和主干；单任务不报不存在的另一头指标 | 是否存在负迁移 |
| 原双头 vs 一致性正则/条件强度头（选做） | 相同训练与发布口径 | 投影改写的偏差能否减轻 |
| 最佳结构O1 vs 最佳候选优化器 | 同loss、增强、种子、算力报告 | 求解算法收益 |

P0至少完成第一行和损失基线；论文如声称二进制/连续结构或优化器有贡献，
对应对照必须补全3种子，缺预算则降为探索性单种子结果。未实施attention模型不得画为最终主线。
不通过的实验保留，不要求所有候选都比简单模型好。

题目三因素属于必做，和模型机制消融区分：

- 类型：7个非空模态组合；
- 位置：start/middle/end三位置，并报告实际被遮挡索引；
- 时长/缺失比例：0.1/0.3/0.5三档及实际连续长度；
- 交互：至少“类型×比例”热图；多模态同步/独立窗口对照用于说明位置耦合；
- 按短/中/长有效序列、自然视觉全缺失、真值类别、强情感`|y|≥2`分层作错误归因，
  使用预定义分层并报告样本数，不从错误样本反选最有利组。

规律必须来自实际结果，不强制性能单调下降，也不能为曲线好看删除异常条件。

## 4. 不确定度与统计单位

固定类别顺序Negative/Neutral/Positive；Macro-F1明确`labels=[0,1,2]`，
缺某类时该类F1=0并报告支持数。Pearson只有真值和预测均有方差时可定义，否则JSON写null，不能NaN/0冒充。

所有最终比较保存一行/样本/条件/训练种子的预测，至少：

`candidate,train_seed,bank,condition_id,replica,sample_id,video_id,y_class,y_reg,p_negative,p_neutral,p_positive,raw_intensity,polarity,intensity,mask_sha256`

mask_sha256是该样本最终`[3,50]`布尔张量按C顺序uint8序列的SHA，与对应样本ID绑定。
任一模型mask不同或缺行时不能配对；源文件/标签也须匹配。

**聚类配对bootstrap**：从valid的video_id组有放回抽同样组数，选中组的全部片段、
全部条件、全部复本、全部训练种子共同进入该次draw，两个候选用同一draw。
每次先重算各条件/种子指标，再按原协议顺序取平均，最后对10000个平均差取2.5/97.5百分位。
禁止先求每种子CI再平均上下界，禁止以21个条件或105个复本作为独立样本。
所附`evaluate_predictions.py`实现这一口径（固定已训练预测，不重训练）。

训练种子间SD另列；bootstrap只度量固定模型、固定数据协议下按视频抽样的不确定性，
不涵盖所有训练数据重采样误差。胜/平/负注明统计单位；不以3个种子Wilcoxon断言显著。
若需要正式多个检验，用视频组级配对置换、同一组在所有条件同步交换两候选预测，
Holm校正预注册的主要对比族；不是完成题目必需项。

CI跨0只说明证据不足，不能宣称两模型等效。性能差很小而权重/耗时显著变大时优先简单模型。
confirm使用了新mask但相同valid样本，不构成新验证人群。历史test已经曝光，
最终test报告须写明本项目历史使用，不把本轮单次执行表述为项目首次测试。

## 5. 验收门

### 输入与数值

- train3395 / valid728 / test727、附件3恰好30个文件；ID/组无跨划分交叉。
- 分类映射与强度符号一致，近零标签不重写；源文件SHA在执行前后相同。
- 原始float32掩码先于归一化/压缩；train-only统计；valid/test不fit任何变换。
- 原始自然缺失、合成缺失、padding/特殊位置可分别追踪；新mask不恢复旧缺失。
- 全缺失softmax与空模态输出有限，fallback不删样本；PAD扩展/值变化不影响输出。
- 缺失窗口连续；比率实际值、跳过情况、长短位置表均落盘。
- 冻结编码器梯度为None，dropout关闭；文本先遮挡再编码；缓存无完整文本旁路。
- 禁止附件3/4做训练、模型选择、阈值调整或定制增强。

### 性能与证据

- 至少B0/B2/M1全量结果，clean和select缺失库四指标完整；已选方案三种子或明确provisional。
- 缺失类型、位置、时长必做；raw/published、自然缺失/新增缺失、各类支持数齐全。
- 所有候选输入ID、mask摘要完全一致；随机种子/软件/硬件/梯度预算可查。
- 无未解释训练失败；零失败日志不代替检查预测值、类别和覆盖。
- 提供混淆矩阵、MAE/F1随缺失率曲线、类型×比例热图、位置对比、学习曲线与错误表；
  由CSV生成，优先SVG/PDF，图注写清样本/视频数和区间口径。

### 推理与提交

- 模型、normalizer、mask协议、编码器与发布规则先写`freeze_manifest.json`，
  同一冻结对象完成test与附件3推理。不得测试后回调参数。
- 附件3 CSV：`sample_id,原文件名,polarity,intensity`；UTF-8 BOM、数值六位小数。
  ID集合为`附件3_01`至`附件3_30`，原文件名保留`.pkl`。
- 极性枚举严格Negative/Neutral/Positive，强度有限且[-3,3]，中性=0、负<0、正>0；
  序列化读回再查，与JSON一致，不用伪标签计算指标。
- 干净进程离线加载提交必需权重，重推30条与冻结结果一致（FP32绝对误差≤1e-5，
  CSV六位读回误差≤5e-7）；舍入边界处极性必须相同。
- 最终只打包推理所需模型state，不打包optimizer、grad、日志大文件或train缓存；
  未量化权重先测体积。量化/FP16部署必须重新在valid验证，不直接降精度。
- Q1已有ZIP为24,015,744字节。最保守地把它作为整体与Q2合包，再额外计入小BERT仍有剩余；
  最终建议展开三问白名单统一打包并对同SHA的小BERT去重，给Q3和代码至少预留5MB。
  具体以最终压缩字节数为准，不能用参数数目或单问包估算替代50MB验收。

```text
  environment.lock.txt  environment.json  execution_plan.json
  preflight.json  training_history.jsonl  failures.jsonl  resource_usage.csv
  normalizer.npz  checkpoints/  metrics.csv  predictions/

```

完成run再生成SHA清单；报告后补必须更新该run自己的清单并记录，避免再次出现“数值通过、报告hash失败”。
提交前运行原文件保护审计，git diff只能落在`问题二/`。原数据、ds、第一问定稿和远端旧结果保持原样。
